# T1 — خطة أول فرق بنيوي للمظاهر الدائمة

**الحالة:** مقترح تخطيط موثّق بطلب المالك في 2026-09-06؛ ليس تفويض تنفيذ أو قبولاً بصرياً أو اعتماداً للمرشحات.
**أساس القراءة الأصلية:** `9f1e0f5d0c75604704a4f77f1d8474ee785b2195`؛ **أساس التوثيق:** `378c152df0acec4a623911f750927e0060cec482`، ويشمل تصحيح فصل الثيم عن المظهر.
**المرجعية:** [ADR-115](ARCHITECTURE_DECISIONS.md#adr-115--permanent-experience-tracks-evolve-through-controlled-candidates-owner-decision-expanded-2026-09-06)، [تعليمات الواجهة](../apps/frontend/AGENTS.md)، [تصحيح المصطلحات](CINEMATIC_REDESIGN_2026-09-05.md)، والمخطط الحاكم [BP §4.4 و§4.6](movie_taste_platform_blueprint_ar.md).
**حدود السلطة:** هذه خطة مشتقة تحت ADR-115؛ المالك يحسم القبول والاعتماد، والمنسق يفتح التنفيذ ويثبت الملكية والتبعيات من اللوحة الحية.

## 1. الرحلة والنطاق

الرحلة المختارة: **التوصيات ← فتح العمل أو حفظه**. جولة التنفيذ الأولى تغيّر مقدمة العمل المميز أعلى التوصيات وحدها؛ الرفوف والتفاصيل مرجع سلوكي للتحقق وخارج التعديل.
السبب: موضع قرار مركزي يسمح باختلاف التكوين والكثافة وموضع الإجراء دون تغيير المحرك أو توسيع العمل إلى جميع الشاشات.
عند أساس القراءة، [RecommendationsScreen.tsx](../apps/frontend/app/components/RecommendationsScreen.tsx) يختار العمل المميز ويعالج الحفظ خارج كتلة العرض المشتركة، ثم يعرض الصورة والعنوان والسنة والأنواع ومسار التوصية وزرّي الفتح والحفظ.
`Baseline v1` معتمد بصرياً لكنه سابق للقياس ولم يحقق التمايز الكامل؛ لا يُعامل بوصفه فائزاً مثبتاً. تُراجع هذه الملاحظة مقابل الكود عند فتح التنفيذ.

## 2. أول حزمة لكل مظهر

الحزم أدناه مقترحات مرشحات؛ توثيقها لا يفتح ثلاث خانات تجريبية نشطة تلقائياً، وكل حزمة جولة تنفيذ محدودة.

| الحزمة | الفرق البنيوي المقترح | الفرضية وإشارة النجاح التكوينية |
|---|---|---|
| C1 — cinema | صورة رئيسية منفردة فوق لوحة عنوان ومعلومات، ثم صف الإجراءين خارج الصورة؛ تسلسل رأسي منخفض الكثافة بدل التكوين المتراكب الحالي، بلا صورة زخرفية ثانية على الكمبيوتر | فصل الصورة عن القرار يحافظ على الحضور السينمائي ويوضح الإجراء؛ يتعرف الشخص على العمل ويفتحه أو يحفظه بلا مساعدة أو بحث عن الزر |
| P1 — premiere | ملصق بجوار لوحة معلومات متوازنة: عنوان ثم الحقائق المتاحة ثم الإجراءان أسفل النص؛ يستمر التجاور على الهاتف ما دامت القراءة سليمة ويتراص عند ضيق المساحة أو التكبير | الموازنة التحريرية تساعد على قراءة الاختيار؛ يحدد الشخص العمل ومسار توصيته ويصل للتفاصيل دون فهمه كترشيح بشري |
| M1 — montage | صف قرار مختصر: ملصق صغير، عنوان وحقائق، ومنطقة إجراء مباشرة؛ يصعد أول رف إلى موضع أقرب، وتلتف الأزرار إلى صف واضح داخل الوحدة على الهاتف | تقليل ارتفاع المقدمة يسرّع الوصول؛ يصل الشخص إلى أول رف ويحفظ العمل المقصود دون نقر خاطئ أو فقدان تعريف العمل |

لا ارتفاع ثابت يخفي النص لتحقيق كثافة شكلية. عند 360×740 بالمقاس الطبيعي يستهدف القبول ظهور عنوان العمل والإجراءين؛ عند التكبير تُقدَّم القراءة والوصول على البقاء داخل الطية الأولى.
هذه فروق بنيوية أولى على سطح واحد، لا ادعاء باكتمال هوية المظهر على مستوى المنتج كله.

## 3. ما يبقى ثابتاً

- العمل المميز ومعرّفات التوصية وترتيب الرفوف وعناصرها وسياق الفتح ومقاصد التنقل؛ لا تغيير لاختيار المحرك أو عدد التوصيات المرسومة.
- النصوص والحقائق المتاحة نفسها؛ لا سبب مولّد ولا عبارة «اختيار المحررين» ولا صورة مشهد مختلقة. تستخدم الصورة الفعلية المتاحة وحالة غيابها الصادقة.
- الحفظ عبر المعالج الحالي: قفل مستقل للعمل، انتظار ثم تأكيد الخادم، خطأ ظاهر وإعادة محاولة عند الفشل؛ فتح التفاصيل لا يغير حالة العمل.
- الملاءمة والجودة والتوفر والثقة معانٍ منفصلة؛ لا دمج درجات أو تغيير قيمة أو لغة تنسيق أو وحدة أو دقة أو مصدر أو تقريب.
- **الثيم** `system / light / dark` يغيّر الجو البصري فقط؛ يبقى التكوين والكثافة والإفصاح وموضع الأفعال ثابتاً داخل المظهر نفسه. `system` يحلّ ديناميكياً إلى فاتح أو داكن.
- **المظهر** `cinema / premiere / montage` يغيّر التكوين والهوية؛ لا يمس حفظ الاختيار الصريح أو الافتراضي، ولا ينسخ منطق الحالة أو البيانات أو شاشات كاملة.
- أسماء وصول محلية على الأفعال، ترتيب قراءة وتركيز مفهوم، وإخفاء الزخارف المتكررة عن التقنيات المساعدة؛ اللون أو الصورة ليسا حامل المعنى الوحيد.
- الخطوط وعلامة Kolme وعائلة الأيقونات والحركة والإفصاح الحالي خارج هذه الجولة؛ يبقى استكمال تمايزها، ومعالجة الأرقام والأثر البصري، التزاماً لاحقاً بمرشحات محدودة وفق ADR-115 لا إعفاءً منه.

## 4. الملفات والمالكون والتعارضات

| المسؤول | الملكية المقترحة وحدودها |
|---|---|
| مالك تنفيذ واجهة واحد يعيّنه المنسق | [RecommendationsScreen.tsx](../apps/frontend/app/components/RecommendationsScreen.tsx): بنية مقدمة العمل المميز فقط؛ [RecommendationsScreen.module.css](../apps/frontend/app/components/RecommendationsScreen.module.css): تخطيط المقدمة ومتغيرات المظهر؛ [RecommendationsScreen.test.tsx](../apps/frontend/app/__tests__/RecommendationsScreen.test.tsx): التكافؤ المرتبط بالمقدمة |
| المنسق | حجز الملفات وإخلاؤها وترتيب الحزم وتحديد نقطة القرار؛ تسجيل بطاقة كل مرشح وقرار إغلاقه في المهمة أو PR القائم، دون إنشاء سجل أو منصة تجارب جديدة |
| مراجع مستقل عن المنفذ | مراجعة أدلة الوصول والعرض والسلوك وإعادة الملاحظات إلى المرشح نفسه |
| مالك المنتج | القبول البصري ثم قرار الاعتماد أو الرفض بعد المراجعة التكوينية |

خارج التعديل: `WorkCard*` و`HorizontalShelf*` و`WorkScreen*` و`page.tsx` و`AppShell*` وموفر المظهر وعقود API والخلفية والتحليلات.
تستهلك الحزم رموز اللون والعمق القائمة؛ الحاجة إلى `cinematic.css` أو `tokens.css` تُرفع كتَبَعية منفصلة لمالكها ولا توسّع الحزمة ضمنياً.
التعارض المؤكد بنيوياً: الحزم الثلاث تمس الملفات نفسها، لذلك تُنفذ بالتسلسل لا بالتوازي، ولا تُنسخ ثلاث شاشات لتجاوز التعارض.
أظهرت القراءة الأصلية صفوف L2 واسعة وتكليف WorkCard مستقلاً؛ تصحيح اللوحة اللاحق جعلها تاريخية لا تمنح ملكية حية. لا تُستعمل هذه الملاحظات لإثبات حجز حالي؛ تُراجع الأقسام الحاكمة الحية قبل التنفيذ.
عند التوثيق، خريطة المنسق تؤجل T1 بعد مسار Gate C وWave 1؛ أي تقديم يقرره المنسق، وأي نشر مؤثر بعد دليل G2 يستدعي إعادة دليله على الإصدار النهائي. لا يُفتح التنفيذ بمجرد حفظ هذه الوثيقة.

## 5. التسلسل وقرار المرشح والتراجع

1. تحديث أساس الكود والتحقق من الملكية وتعليمات الثيم/المظهر، ثم تسمية مالك الملفات والمراجع ونقطة قرار المالك.
2. تسجيل بطاقة الحزمة: المظهر والسطح ونسخة أساسه، صفاته المحمية، فرضية واحدة والفرق المحدد والثوابت، إشارة النجاح وحواجز الوصول والأداء، الأدلة المطلوبة والتراجع.
3. تنفيذ **C1 ثم P1 ثم M1**؛ جولة مستقلة لكل حزمة على الشجرة المشتركة. لا تبدأ التالية على الملفات حتى تسليم السابقة وإخلاء ملكيتها، وأي بنية مشتركة لازمة تخضع لاختبار عدم تغيير المظهرين الآخرين.
4. اجتياز التحقق المحلي ثم عرض مقارنة قبل/بعد للمالك؛ بعدها مراجعة تكوينية بنفس المهمة والبيانات مقابل خط أساس المظهر، وتسجيل الحاجة للمساعدة والالتباس والنقرات الخاطئة.
5. دورة الحالة: `PROPOSED → BUILT → VISUALLY_ACCEPTED → FORMATIVE_REVIEWED → ADOPTED / REJECTED`؛ المراجعة تعيد المرشح نفسه إلى `PROPOSED`، والاعتماد وحده يرفع نسخة خط أساس مظهره.
6. لا مرشح ثانٍ في المظهر نفسه قبل إغلاق الأول بأدلته وقراره؛ اعتماد حزمة متعددة الأبعاد يدعم نتيجة عن الحزمة كلها فقط.
7. التراجع يعيد تغييرات المرشح المحددة إلى خط أساس مظهره مع حفظ الحزم المعتمدة الأخرى والتفضيلات؛ لا حذف لمظهر دائم ولا إزالة تعميمية لتغييرات الآخرين.

## 6. الفحوص المحلية وبوابة القبول البصري

هذه متطلبات تنفيذ مستقبلية، وليست نتائج فحوص أُنجزت في جلسة التخطيط أو التوثيق.

| المجال | المطلوب |
|---|---|
| تكافؤ البيانات والتنقل | العمل نفسه وسياق الفتح والطلبات نفسها في المظاهر الثلاثة؛ لا تكرار عناصر تحكم قابلة للتركيز، ولا آثار جانبية من فتح التفاصيل |
| حفظ وحالة متزامنة | النجاح والفشل والإعادة والاستجابات المؤجلة وتبديل الملف أثناء الطلب؛ تطابق حالة الحفظ بين المقدمة والرف، وبقاء الحفظ المؤكد أمام قراءة أقدم |
| رجوع وتفضيلات | الرجوع من التفاصيل وإعادة التحميل واستقلال المظهر عن الثيم وبقاء الاختيار الصريح؛ دون تغيير عقود التخزين |
| فحوص التنفيذ | أثناء التطوير: `npm run test -w apps/frontend -- app/__tests__/RecommendationsScreen.test.tsx`؛ عند إغلاق الحزمة: اختبارات الواجهة و`npm run lint -w apps/frontend` و`npm run build -w apps/frontend` محلياً؛ استخدام webpack وفق عقد المعاينة القائم إن اقتضت روابط الاعتماد ذلك |
| الأداء | مقارنة قبل/بعد بنفس البيانات والجهاز؛ لا طلبات API أو موارد صور جديدة، ولا انتظار حركة قبل الاستجابة، ولا انزياح تخطيط جديد بسبب الصورة أو الأزرار |
| مصفوفة العرض | معاينة إنتاج محلية ببيانات اصطناعية ثابتة: المظاهر الثلاثة × العربية/الإنجليزية × الفاتح/الداكن على 360×740 و390×844 و430×932 و1440×1000، مع فحص system تحت نظام فاتح وداكن وثبات التكوين بين الثيمات |
| الحالات الطرفية | صورة غائبة أو فاتحة، عنوان طويل، انتظار وفشل وحالة فارغة؛ وحراسة حالات تحميل/جاهزية الشاشة القائمة من الانحدار |
| الوصول | لوحة مفاتيح وتركيز ظاهر وترتيب مفهوم وRTL/LTR وتكبير وتباين WCAG AA وأهداف لمس 44px ومسار Reduced Motion ساكن مكافئ؛ لا تداخل توست أو تنقل مع الإجراء |
| الأدلة والقرار | لقطات مقارنة وسجل نتيجة كل حالة ونسخة الكود في مسار محلي متجاهل ودائم خارج worktree المؤقتة يخصصه المنسق؛ المراجع يفحصها والمالك يقبل بصرياً، فالبناء وحده لا يثبت القبول |

## 7. حدود القياس والقرارات التي تُرفع

لا جمع تحليلات جديد ولا تفعيل `appearance_exposed / selected / changed` ولا توسيع allowlist ضمن T1؛ تبقى شروط الإفصاح والموافقة والإنفاذ في ADR-115 حاكمة.
لا استنتاج تفوق سببي أو فائز عام من قبول المالك أو عدد مختاري المظهر؛ الاختيار ذاتي ويتأثر بالافتراضي والجمهور، والأسباب تحتاج بحثاً طوعياً مباشراً.
لا تتطلب الخطة قرار اتجاه جديداً. تُرفع فقط مقترحات تغيير وعد المظهر أو الحقائق والوظائف المشتركة أو سياسة الافتراضي أو إزالة/دمج مظهر؛ يبقى القبول والاعتماد المعتادان عند المالك.
