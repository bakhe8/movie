## 2. High — reproduced defects

### H1. The triad pool is consumed, never reused; the seed catalog caps every profile at 5 triads for life

`TriadsService.selectRandomTitles()` excludes every title that appears in *any* completed triad (`title.id NOT IN (:...rankedTitleIds)`, [triads.service.ts:125-128](../apps/backend/src/modules/triads/triads.service.ts)). A title therefore enters at most one triad per profile. With W watched titles a profile gets ⌊W/3⌋ triads, ever. With the 15 seeded titles: 5 triads maximum, so the `likely` (≥10) and `strong` (≥20) bands in `RecommendationsService.confidenceBand()` and the ≥5 hold-out in `train_and_evaluate()` are unreachable in the dev environment, and the "20–30 triads per Alpha user" plan (`BP §17.2`) needs 60–90 distinct watched films per user.

Reproduced: a fresh profile with exactly 3 watched titles ranks one triad; the next `GET …/triads/current` answers `400 "Mark at least three films as watched before starting a ranking round"` — a false message, the user *has* three.

Blueprint: `BP §8.1` (verification/refutation triads re-test a tendency; reference films are deliberately repeated), `BP §8.2` (`Repeat` is a *penalty* term, not an exclusion), `product_journey_ar.md` protocol #8. Also `BP §14`: the target `/triads/next` contract already defines `409 { reason: 'need_more_watched', needed }` — a distinct reason is needed for "pool exhausted".

Fix: replace the hard exclusion with a repeat penalty (exclude only the previous triad's titles, or cap appearances per title per N triads); return a machine-readable reason; make the frontend copy follow the reason instead of always printing "mark at least three". Add a unit test that a profile with 3 watched titles can rank more than one triad.

### H2. A deactivated account keeps API access for up to 7 days

`AuthService.login()` rejects `active = false`, but `AuthService.validateUser()` — what `JwtStrategy.validate()` runs on every guarded request — does not check `active` ([auth.service.ts:111-125](../apps/backend/src/modules/auth/auth.service.ts)). Reproduced: after `UPDATE users SET active=false`, `GET /api/profiles` with the account's existing JWT → **200**; `POST /auth/login` → 401.

`BP §21.3` (account takeover controls). Fix: `if (!user || !user.active) return null;` plus a unit test and an e2e test; keep in mind ADR-26's refresh-token work must not reintroduce this.

### H3. The trainer cannot start on a machine without `OPENAI_API_KEY`

`services/workers/src/__init__.py` imports `enrichment`, and `enrichment.py:19` builds `openai.OpenAI(api_key=os.getenv("OPENAI_API_KEY"))` at import time; the OpenAI SDK raises when the key is missing. `python -m src.training <id>` therefore dies at import, before `load_dotenv()` in `train_profile()` ever runs. Reproduced with `env -u OPENAI_API_KEY python -c "import src"`.

[QUICKSTART.md](QUICKSTART.md) §Prerequisites says an OpenAI key is *not* needed for the core loop — false today. It only works on this machine because a real key is exported in the developer's shell (see §8).

Fix: construct the client lazily inside `FilmEnrichmentWorker` (per call or in `__init__`) and stop importing `enrichment` from the package `__init__`.

### H4. Any malformed id in a path returns 500

No `ParseUUIDPipe` on `:profileId`, `:titleId`, `:triadId`; Postgres rejects the cast and Nest answers `{"statusCode":500,"message":"Internal server error"}`. Reproduced for `GET /api/profiles/not-a-uuid` (authenticated) and `GET /api/titles/not-a-uuid` (public). Cheap noise generator for error monitoring, and the wrong contract (should be 400 or 404).

Fix: `@Param('profileId', ParseUUIDPipe)` everywhere (or a global pipe), one e2e test.

### H5. `docker compose` never reads the root `.env`; a fresh clone gets a Postgres password that the backend does not use

The scripts run `docker-compose -f docker/docker-compose.yml …`; Compose resolves `.env` from the *project directory*, which is the directory of the compose file (`docker/`), where no `.env` exists. Interpolation therefore falls back to `POSTGRES_PASSWORD: postgres` — confirmed by `docker compose … config` and by the container's environment. The backend, seed, CLI and trainer use the root `.env` value (`dev_password_change_in_production`).

Reproduced from the host over TCP with `pg`: password `postgres` → *"password authentication failed"*, the `.env` password → OK. The existing volume was evidently initialised under different conditions, which is why it works on this machine and will not on a fresh clone (`npm run docker:up && npm run db:migrate` → authentication failure). The e2e `postgres-test` service is unaffected because its credentials are hard-coded.

Fix: `--project-directory .` (or `--env-file .env`) in every compose invocation in `package.json`, `apps/backend/package.json` and the `Makefile`; or move the compose file to the root. Add the check to QUICKSTART's troubleshooting table.

## 3. Medium

### M1. `PATCH …/titles/:titleId/state` silently wipes `notes`

`UserTitleStateService.upsert()` sets `state.notes = dto.notes ?? null` ([user-title-state.service.ts:39](../apps/backend/src/modules/user-title-state/user-title-state.service.ts)) — a PATCH that omits `notes` deletes existing notes. Reproduced. Same shape of bug for `watchedAt`: a supplied `watchedAt` is stored even when the new state is not `watched`. Fix: only touch fields present in the DTO; ignore `watchedAt` unless `state === 'watched'`.

### M2. The whole catalog, including full fingerprints and external ids, is public and unauthenticated

`GET /api/titles` and `GET /api/titles/:id` have no guard and return `fingerprint` (13 dimensions + provenance) and `externalIds`. Only the global 60 req/min throttle stands between a scraper and the catalog. `BP §21.3` lists API scraping with quotas as a threat; `BP §5.3` says the work page shows a fingerprint *summary of reviewed features only*; [DATA_LICENSING.md](DATA_LICENSING.md) makes derived features a licensed asset. Fix: require auth for catalog reads (the only client is the app) and strip `fingerprint`/`externalIds` from list responses; expose a reviewed summary on the work page later.

### M3. Duplicate-email race in `register` becomes a 500

`AuthService.register()` does `findOne` then `save`; two concurrent registrations of the same email make the second hit the unique constraint, which is not caught (ProfilesService *does* catch `23505`). Fix: catch and map to `ConflictException`.

### M4. The frontend logs the user out on any transient error

`SessionProvider`'s `ensureProfile().catch(…)` treats *every* failure (network down, 500, 429) as "token invalid" and deletes the stored session ([session.tsx:73-83](../apps/frontend/app/lib/session.tsx)). Fix: only on `ApiError` with status 401.

### M5. Frontend error handling is absent or misleading

- `RankScreen`: every `ApiError` from `getCurrentTriad` renders the "mark at least three films" copy regardless of status; `submitRanking()` has no `catch` (a 400/429/500 is an unhandled rejection and the user sees nothing); a network error leaves an empty card list with a live Save button.
- `DiscoverScreen`: `listTitles` and `markWatched` have no `catch`.
- `ListScreen`: a `getWatchedTitles` failure is an unhandled rejection.
- The global throttle (60/min) is reachable by one user (3 title fetches per triad + one search per keystroke after debounce) and a 429 has no UI path.

Fix: reason codes from the API (see H1), one error banner component, and batch the triad's titles into the triad response (already the `/triads/next` target shape).

### M6. Tailwind 4 is installed, advertised and unused

Zero utility classes in any component; `globals.css` places `@import "tailwindcss"` *after* other rules (invalid `@import` order in plain CSS; the PostCSS plugin tolerates it), and the built bundle contains Tailwind's preflight (`text-size-adjust`, `@layer base`) which silently resets element defaults under the hand-written CSS. `README.md:13` and `ARCHITECTURE.md:14,151` present Tailwind as part of the stack. Also `globals.css` is minified into three lines with duplicated, overriding `.rank-card` rules and poster `img` rules for posters that do not exist — unmaintainable. Decide: adopt Tailwind (and use it) or remove `tailwindcss`, `@tailwindcss/postcss` and the import; expand the CSS into readable source either way.

### M7. `pyproject.toml` does not describe the environment that runs

Declared: Python `^3.11`, `numpy ^1.26`, `pytest ^7.4`, `ruff ^0.1`, plus `sqlalchemy`, `redis`, `black`, `isort` (none imported anywhere). Running: Python 3.14, numpy 2.3.4, scipy 1.17, pytest 9, ruff 0.14 — installed with pip, no `poetry.lock`, Poetry not installed. `numpy 1.26` has no 3.14 wheels, so `poetry install` (Makefile `install`, QUICKSTART §1, ADR-1, RANKING_ALGORITHM §15 "Poetry script") cannot work on the documented platform. Fix: one truthful dependency file (Poetry with a committed lock and a 3.12/3.13 pin, or `requirements.txt`/`uv`) and CI that installs from it; remove the four unused packages.

### M8. Dead dependencies and dead schema in the backend

Never imported: `bullmq`, `redis`, `pgvector` (mentioned only in a comment), `@nestjs/cli`, `@nestjs/schematics`, `tsx`. The `embeddings` table and `Embedding` entity have no reader or writer. ADR-10/25 say Redis is idle *by design*; that is a reason not to install its client yet. Every unused package is audit surface (this repo already spent two commits on dependency CVEs). Remove until needed.

### M9. UI language is session state, not the profile's

`page.tsx` keeps `lang` in `useState('ar')`; `profile.preferredLanguage` is never read, and the toggle is not persisted, so a reload returns to Arabic and the backend field is decorative. `BP §4.1` binds language to the profile (display only). Fix: initialise from the profile and `PATCH` it on toggle.

### M10. Throttling is keyed by raw connection IP

No `trust proxy` configuration and the default `ThrottlerGuard` tracker: behind any reverse proxy (every staging/prod topology in ADR-24) all users share one 60 req/min bucket, and `/auth/*`'s 5/min brute-force limit becomes 5/min for everyone. Fix before staging: `app.set('trust proxy', …)` scoped to the proxy's address plus a `getTracker` that reads the forwarded address; e2e test with a forwarded header.

### M11. Redis and Postgres are published on all interfaces without auth

`docker port`: `0.0.0.0:5433`, `0.0.0.0:6379`. On a laptop on a shared network that is an open Redis. Bind to `127.0.0.1:` in `docker-compose.yml`.

### M12. The explanation generator sends user data to the LLM

`FilmEnrichmentWorker.generate_recommendation_explanation()` puts the user's preference weights and "previous favorites" into the prompt. ADR-23 and [PRIVACY.md](PRIVACY.md) §6.1 forbid sending preferences or watch history; `BP §15.2` allows only an evidence payload of film features. Unused today, so no data has flowed — but it must be rewritten (template from feature evidence only) before it is wired in, and FINGERPRINT_SCHEMA §7 should reference it as a known violation until then.
